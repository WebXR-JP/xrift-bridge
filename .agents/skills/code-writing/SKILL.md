# コード記述共通ルール

## 設計に関する指針

- 長期的な設計のクリーンさを重要視する
- 目先の目的を遂行するためだけの短絡的な修正を避ける
- 不要な自作を避ける。まずは適したライブラリを探す
- 全ての編集時において、その場のスコープ内で解決するよりもよりクリーンな設計を思いついた場合、ユーザーや上位のエージェントに対してその内容を提案すること

## コーディングポリシー

- コードを書かずに解決する。記述は少なく、不要な抽象化はしない
- 嘘を書かない。名前と挙動を一致させる
- 振る舞いだけ書く。データのハードコードを避ける
- 責任の分離。各クラスは単一の責務を負う
- コードの管理コストはそれが解決する問題を上回るべきではない
- 修正後に修正前よりわかりやすくなっていること

## Slopを防ぐために気をつけること

- 不要なフォールバックを書かない。
  - 実行時に発生しないことが想定される分岐はdefault fallbackなどを避けテストなどで到達しないことを確認する
- 責務の重複を避ける
  - 同じ役割の処理を複数箇所にコピペしていたり、try-catchを多段化するなどは避ける
- 処理負荷が大きくなりすぎることが予想されるコードをなるべく書かない
  - その時点で他の選択肢が取れない場合は必ずADRコメントとして理由を書き、レビューなどでなるべく拾われるように心がけること
- 未配線、到達不能コードを残さない。
- オーバーエンジニアリングを避ける
  - テストのための仕組みなど、機能を提供するための実装以外の層が厚くなりすぎないようにする
- 各種コード記述ルールに違反している、そぐわない既存の記述を見かけた場合、そのエージェント自身の責務で編集可能な範囲であればその場で改善や削除などを行うこと
  - そのときの自分自身の責務でそれができない場合、呼び出し元に改善提案、報告を行うこと

## コードの書き方について

- 全てのコメントは日本語で記述すること
- 改修時、参照されなくなったコードは削除する
- ローカルスコープの設計判断において自明ではないもの、意図しない変更が予想されうるものについては必ずADRコメントを書くこと
- 定数にはその値が仮、なんとなく置いた値なのか明確な意図をもって値なのか分かるようにコメントを書く
- 記述する言語に基づいて、[Rust](../../../apm_modules/halby24/agent-common-package/.apm/skills/rust-writing/SKILL.md)、[TypeScript](../../../apm_modules/halby24/agent-common-package/.apm/skills/ts-writing/SKILL.md)の各スキルも参照すること

## コメントについて

コードを記述する際、新規で書くコメントだけでなく既存のコメントについても下記内容に基づいて適宜修正すること

### どのようなことを書くべきか

- その設計を採用した理由
- その設計によるトレードオフ (存在する場合)
- 暗黙の前提条件があるか
- 副作用があるか
- 競合・優先ルールはあるか
- デフォルト値に意味があるか
- 将来的な変更で壊れやすい点があるか
- 状態や不変条件、前提条件は客観的な現在形・条件記述で書く（「〜である場合」「〜のとき」とし、「〜だった」等の過去形やコードの擬人化を避ける）
- 特にテストの説明については具体的に何をやっているのかについては短く留め、それによって何を確かめたいのか、何であることがわかるのかということに重点を置いてわかりやすく記述すること
  - 内容が複雑な場合は短時間でやりたいことが直観的にわかるまとめ内容も記載すること

### 存在すべきでないもの

- 陳腐化したコメント、実装や仕様と異なるもの、実質的な意味のないもの
- 名前やコードを見れば直ちにわかること、実装そのものの内容
- 過去の動作、仕様や変更履歴に言及しているもの
- 重言（トートロジー）（例: 「閾値の値を返す」「IDの識別子を返す」）
- 一時的な開発フェーズ名（「MVP」「第1フェーズ」等）のAPIコメントへの過度な露出（将来の拡張時に陳腐化するため、仕様そのものを記述する）
- シグネチャと乖離した用語や不適切な助数詞（例: メソッド名 `material_slot_count` に対して「外観参照の個数」とだけ書く、行列の数を「本数」と数えるなど）

### Docコメントとインラインコメント

- 呼び出し時に必要な内容はdocコメントに、実装や改修の際に必要な内容はインラインコメントに
- 日本語表現や専門用語の書き分け、翻訳調の回避は[文書作成スキル](../../../apm_modules/halby24/agent-common-package/.apm/skills/document-writing/SKILL.md)に準拠すること
