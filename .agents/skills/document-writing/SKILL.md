# 文書の書き方

ここで記載しているルールはこのリポジトリのオリジナルのドキュメントに対して適用される
submoduleや外部から持ってきてパッチしているものなどには適用せず、元の書き方を尊重する

## 基本ルール

- 日本語で書く。
- 過去について書かない。今または将来のことだけ書く。
- 見出しに数値を付けない (`## 1.1 hoge` などはだめ)
- 未定義の語を説明なしに使わない
  - そもそも独自用語の使用は少なくする
- このスキルの内容に明らかに従っていないドキュメントを編集するときは全体を直す

## ルールの書き方

ドキュメントのその内容がAIエージェントが守るべき内容として書かれる場合、以下のことに気をつけて

- **具体化しすぎない**
  - 目標そのものを書き、目標を達成するための具体的な手法について書きすぎない
- **同じことを何度も書かない**
  - 担当者が肯定文のみから意図を汲み取ってくれることを期待してよい
  - 特に肯定文と否定文が並ぶ構造において、否定文を消しても概ね目指している内容が変化しないならば書かないことを優先する
    - "〇〇であることを確認、××だけして完了としない"　という文は実質的に前半だけでよいことが多い

## 読みやすさのためのルール

- 口語を混ぜていい。文体を柔らかめにする。
- 論理構造を厳密に表現するよりも書かなくても伝わることを省くことを優先する
- 同じ意味を常に同じ単語で表現する必要はなく、だいたい伝わればOK
  - 例: SSoTと正本
- 単語選びでも柔らかさを優先する
  - 可読性→読みやすさ、過度な→〇〇しすぎ、簡潔に→短めに
- 複数の内容が実質的に同じことを言っている場合、なるべくまとめる

## 内容について

異なるドキュメント、ソースコード、スキルなどに同じ情報を書くと陳腐化しやすいので、SSoTと参照で構成する
どれを正本にするべきか判断しかねる場合はユーザーまたは上位エージェントに確認して

## 報告

このスキルの内容に違反しているドキュメントを見つけた際は簡単に報告すること

## 新規作成ドキュメントについて

人間と共同で新規にドキュメントを作成する場合、初期段階ではできるだけ内容を小さくまとめること。
より抽象的、コンパクトなところから始めて徐々に内容を膨らませていくべきである
