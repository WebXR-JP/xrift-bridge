# ブリッジアプリ検証計画

アプリ固有の観測項目と判定観点を示す。手順の詳細まで作り込まない。

## 正本分担

- 設計判断の正本は [ブリッジアプリ](../../design/bridge-app.md)、接続認可・切断失効・サーバー管理境界としての公開は [ブリッジ接続](../../design/bridge-connection.md)、輸送・配送・方向・終了の契約は [プロトコル](../../design/protocol.md) とする。
- 形状（型・フィールド名・操作名・定数値）はコードを正本とし、ここでは複製しない。
- 接続の観測手順・試作条件・計測項目は [接続の検証計画](bridge-connection.md) を正本とする。本文書はアプリ固有の観測だけを扱う。

## セッション公開の観測

- 未認可セッションが公開されないこと。
- 一覧と通知の整合（購読から一覧取得での初期同期、重複除去、終了通知の一度きり）。
- 同名セッションの再作成（終了後の同名を古い割当てと混同しないこと）。
- 別接続での同名（表示・関連付け情報としてのみ扱うこと）。
- 対象接続の切断時の即時失効（終了開始で全セッションを失効させること）。

## 割当ての観測

- capability 不一致の割当てを拒否すること。
- 二重割当て（同一セッション・同一接続口への重複）を拒否すること。
- 解除後の操作拒否（解除後の送信・購読を禁止すること）。
- プラグイン削除で対象セッションを中断すること。
- 未割当ての `reliable` セッションへの到着で理由付き中断すること。

## 診断の観測

- 同梱診断プラグイン経由の echo・ping 往復が成立すること。
- 輸送統計から診断項目が除かれ、keepalive Ping と区別できること。

## 統合の観測

- 実 GUI から実ワールドへのテキスト表示が往復すること。
- 切断後の送信が不可になること。
- 再接続後に再承認が必要になること。

## 基盤の観測

- Electrobun 上での既存 `ws`・yamux の動作。
- 画面との通信用 RPC の往復。
- 埋込み UI の表示。
- 終了処理（起動・終了、切断時の失効を含む）。
- パッケージ化の可否。
- 配布サイズ・常駐メモリを記録する。軽量性が採用理由であるためである。

## Angular 移行の gate

- 機能・実 Webview・人間の確認が揃った時点で既定を Angular に切り替える。切替え後に vanilla mainview は削除し、二重実装・フォールバックは残さない。
- gate の証拠：純粋・契約試験の緑、TestBed・実テンプレート試験の緑、実 Webview での往復（開発専用操作・観測口の段階観測：操作受付・業務結果・snapshot revision・DOM 反映）、人間確認の記録。描画・フォーカス・操作フローの最終確認は人間の GUI セッションで行い、native 画素・実入力の自動化は証拠条件に含めない（非目標）。

## 試験層

- 純粋関数・契約は既存 `vp test` で行う。
- TestBed・実テンプレートは公式 `@angular/build:unit-test` の Vitest runner で行う。パッケージ `test` から両者を呼び、`vp run -r test` に組み込む。
- 変更検知は zoneless＋signals とする。
- happy-dom の通過を native 描画の証明にしない。native 画素・実入力の自動化は行わず、描画・フォーカス・操作フローの最終確認は人間の GUI セッションで行う。
- なお「証拠の残し方」節の残存リスクの記述は移行前の記録であり、現状の試験層は本節を正本とする。

## AI 観測口の拒否試験

- 有効化の三条件（開発ビルド・明示 opt-in・隔離実行）を欠く場合は待受けを開かない。stable は環境変数を設定しても開かない。
- 拒否試験：非 loopback、token 不一致・再利用、Origin／Host 不一致、検証外入力、サイズ・期限超過、ブラウザ向け CORS の到達、任意 JS・関数名指定・DOM 全文・実体取得口の要求、比較コード取得からの自動承認。
- `ng.*` は可否・件数等の補助観測だけに使い、実体取得の迂回に使わない。
- 汎用ジョブ履歴・再送基盤は作らない。

## 証拠条件（Angular 移行）

- 自動側の正本は開発専用の操作・観測口の段階観測（操作受付・業務結果・snapshot 採用・Angular の DOM 反映）とし、別々に返す。RPC 成功や rAF を描画完了と呼ばない。
- DOM 観測は固定要素キー・矩形・表示／disabled・`document.hasFocus()`・activeElement キーだけとし、入力値・本文は残さない。比較コード本文・業務 payload は残さない運用を変えない。
- native 画素観測・実入力送信の自動化は非目標であり、証拠条件に含めない。描画・フォーカス・操作フローの最終確認は人間の GUI セッションで行う。

## 証拠の残し方

- 項目ごとの合否と判定観点を、版と識別子付きで残す。
- 成功と失敗のどちらも残す。
- 設計判断の変更が必要になった場合は観測で補完せず、設計へ戻す。
- 残存リスク: GUI の表示層（mainview の描画・入力検証・revision 採用）と RPC 層は自動試験の対象外であり、backend の試験と人間の GUI 確認に依存している。

## 実機不具合と修正（2026-10-16）

既存の節は書き換えない。本節は新中継契約の実機での不具合と修正の記録である。設計判断は設計文書を正本とし、形状・型・値はコードを正本とする。

- 症状：プラグイン操作画面で子画面が「子画面の遷移規則が期待値と一致しないため回収した。」で回収された。
- 原因：子タグの `navigation-rules` 属性には JSON 文字列を設定するが、Electrobun の preload がそれを JSON.parse して `string[]` 配列にし、`BrowserView` は実行時に配列を保持する（型宣言は `string | null` だが実行時実体は配列。旧計測ログの `navigationRules=^*,views://plugin-host/*,...` は配列をテンプレート文字列化したもの）。こちらの照合が `JSON.parse(actual)` を呼ぶため配列が不正 JSON となり不一致になっていた。自動試験の偽画面が JSON 文字列を返しており実表現と食い違っていたため検出できていなかった。
- 修正：照合を実表現対応にした（配列はそのまま検査、文字列は `JSON.parse`、順序付き完全一致＝trim 比較、静的登録から期待値生成、不一致は endpoint 生成前に回収、という安全境界は維持）。偽画面を実表現（配列）に統一し、配列／JSON 文字列の双方と拒否表（追加・欠落・並替え・非文字列・`null`・不正 JSON）の試験を追加。コミット `1b83b4c`。
